# Task 3.4 — Responsive UI Audit

> **Phase:** 3 — Frontend Stabilization
> **Trạng thái:** ✅ Hoàn thành
> **Độ khó:** Trung bình
> **Yêu cầu trước:** Task 3.1, 3.2 và 3.3

## Mục tiêu

Rà soát các layout chính ở kích thước desktop và mobile, tập trung vào
overflow ngang, điều hướng và các form/bảng có chiều rộng cố định.

## Thay đổi đã thực hiện

- Admin layout:
  - sidebar chỉ hiện từ breakpoint `lg`;
  - thêm mobile top bar;
  - thêm menu quản trị đóng/mở;
  - menu có vùng scroll riêng khi danh sách link dài;
  - main content dùng `min-w-0` và padding responsive.
- Public header:
  - chuyển desktop navigation sang breakpoint `xl` để tránh chật ở tablet;
  - mobile menu giữ nguyên và nút menu không bị co;
  - logo/title dùng gap responsive và vùng text có thể co.
- Login:
  - grid mobile dùng cột `minmax(0, 1fr)`;
  - form/input/button khóa theo chiều rộng container;
  - tiêu đề trường giảm cỡ trên mobile và tự xuống dòng.
- Footer:
  - brand block có `min-w-0`;
  - tên trường có thể wrap trên màn hình hẹp.
- Rich content:
  - bảng HTML có thể cuộn ngang trong vùng nội dung;
  - không làm vỡ layout bài viết khi bảng rộng.
- Homepage hero:
  - title chia dòng có chủ đích trên mobile;
  - mô tả ngắn hơn ở mobile để giữ CTA trong viewport;
  - giữ bản mô tả đầy đủ trên màn hình từ `sm`.
