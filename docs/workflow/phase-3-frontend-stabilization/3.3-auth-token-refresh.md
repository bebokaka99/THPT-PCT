# Task 3.3 — Auth Token Auto-Refresh

> **Phase:** 3 — Frontend Stabilization
> **Trạng thái:** ✅ Hoàn thành
> **Độ khó:** Cao
> **Yêu cầu trước:** Auth/JWT, PostgreSQL migrations và API client dùng chung

## Mục tiêu

Tự khôi phục phiên đăng nhập và tự cấp lại access token khi hết hạn, đồng thời
không tiếp tục lưu access token trong `localStorage`.

## Thiết kế đã triển khai

- Access token:
  - JWT thời hạn ngắn theo `JWT_EXPIRES_IN`;
  - chỉ giữ trong memory của `AuthProvider`;
  - không còn lưu vào `localStorage`.
- Refresh token:
  - opaque random token 48 bytes;
  - browser chỉ nhận qua cookie `HttpOnly`;
  - database chỉ lưu SHA-256 hash;
  - cookie dùng `SameSite=Lax`, `Secure` trong production;
  - refresh thành công luôn rotation token cũ.
- Logout revoke refresh session hiện tại và xóa cookie.
- API client chỉ thử refresh khi request có Authorization và nhận 401.
- Các request 401 đồng thời dùng chung một refresh promise để tránh refresh
  storm.
- Reload ứng dụng gọi `/api/auth/refresh` để khôi phục session.

## Database

Migration:

```text
database/postgresql/migrations/016_create_auth_refresh_sessions.sql
```

Bảng `auth_refresh_sessions` lưu user, token hash, hạn sử dụng, thời điểm revoke
và lần dùng cuối.

## API mới

```text
POST /api/auth/refresh
POST /api/auth/logout
```

`POST /api/auth/login` giữ response cũ nhưng bổ sung refresh cookie.

## Cấu hình

```env
JWT_REFRESH_EXPIRES_DAYS=7
```

CORS bật credentials cho các origin nằm trong allowlist.
