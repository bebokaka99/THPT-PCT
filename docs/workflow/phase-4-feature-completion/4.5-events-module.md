# Task 4.5 — Events Module

> **Phase:** 4 — Feature Completion  
> **Trạng thái:** ✅ Hoàn thành  
> **Độ khó:** Cao  
> **Yêu cầu trước:** Auth/RBAC, Media, PostgreSQL migration workflow

## Mục tiêu

Hoàn thiện module sự kiện từ database đến public website và admin portal. Sự
kiện mới mặc định ẩn, chỉ xuất hiện public khi admin chủ động công khai.

## Database

Migration:

```text
database/postgresql/migrations/018_complete_events_module.sql
```

Bổ sung cho bảng `events`:

- `slug` unique;
- `category`;
- `cover_image_url`;
- `all_day`;
- `is_public`;
- index theo visibility/start time và status/start time.

Migration giữ nguyên dữ liệu cũ và backfill slug dạng `event-{id}`.

## Backend API

### Public

```text
GET /api/events?page=1&limit=10&q=&scope=upcoming|past|all&status=
GET /api/events/:slug
```

Public API chỉ trả `is_public = true`.

### Admin — permission `events.manage`

```text
GET    /api/events/admin
GET    /api/events/admin/:id
POST   /api/events
PATCH  /api/events/:id
PATCH  /api/events/:id/publish
PATCH  /api/events/:id/hide
PATCH  /api/events/:id/cancel
PATCH  /api/events/:id/complete
DELETE /api/events/:id
```

Validation:

- title/start time bắt buộc;
- end time không được trước start time;
- status chỉ nhận scheduled/cancelled/completed;
- cover chỉ nhận HTTP/HTTPS hoặc `/uploads/images/`;
- limit tối đa 50;
- slug unique.

## Frontend public

- `/su-kien`: tìm kiếm, tab sắp diễn ra/đã diễn ra, pagination.
- `/su-kien/:slug`: cover, lịch, giờ, địa điểm, mô tả.
- Header có navigation `Sự kiện`.
- Homepage có section `Sự kiện sắp diễn ra` từ API thật.
- Card hỗ trợ trạng thái đã hủy/đã kết thúc và empty/loading/error states.

## Admin UI

- `/admin/events`: danh sách và actions công khai/ẩn/hủy/hoàn tất/xóa.
- `/admin/events/new`: tạo sự kiện.
- `/admin/events/:id/edit`: sửa sự kiện.
- Form hỗ trợ:
  - title, slug, category, description, location;
  - start/end, all-day;
  - trạng thái lịch và visibility;
  - cover URL hoặc chọn từ Media.
- Các trang admin event được lazy-load.
