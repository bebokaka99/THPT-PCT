## Mô tả vấn đề

Tất cả search queries dùng `LIKE '%keyword%'` → không thể dùng index → full table scan.
Module search (`/api/search`) cũng dùng LIKE trên cả posts, documents, categories.

---

## Mục tiêu

> **Ghi chú triển khai:** Project hiện dùng PostgreSQL. Vì vậy migration và query
> bên dưới được triển khai bằng GIN `tsvector`/`plainto_tsquery`; các ví dụ
> MySQL `FULLTEXT`/`MATCH AGAINST` trong phần kế hoạch cũ không áp dụng trực tiếp.

1. Thêm MySQL FULLTEXT indexes cho posts (title, content, excerpt) và documents (title, description)
2. Chuyển search queries từ LIKE sang `MATCH ... AGAINST`
3. Giữ LIKE làm fallback cho queries ngắn < 3 ký tự (FULLTEXT minimum)

---

## Cách thực hiện

### Plan A — MySQL FULLTEXT indexes

**Bước 1:** Tạo migration `database/schema/015_add_fulltext_indexes.sql`
```sql
ALTER TABLE posts ADD FULLTEXT INDEX ft_posts_search (title, excerpt, content);
ALTER TABLE documents ADD FULLTEXT INDEX ft_documents_search (title, description);
```

**Bước 2:** Sửa `post.repository.ts` — `findPosts` search
```ts
if (query.q && query.q.length >= 3) {
  where.push('MATCH(p.title, p.excerpt, p.content) AGAINST(? IN BOOLEAN MODE)');
  params.push(query.q + '*');
} else if (query.q) {
  where.push('(p.title LIKE ? OR p.excerpt LIKE ?)');
  const kw = `%${query.q}%`;
  params.push(kw, kw);
}
```

**Bước 3:** Sửa tương tự cho `document.repository.ts`

**Bước 4:** Sửa `search.repository.ts`

**Bước 5:** Test với data thật

### Plan B — Nếu FULLTEXT index creation fails (table locked)

Chạy migration offline hoặc dùng `ALTER TABLE ... ALGORITHM=INPLACE`

### Plan C — Bỏ qua, dùng LIKE với index prefix

Nếu data dưới 5K records: giữ LIKE, chỉ thêm regular index trên title column.
