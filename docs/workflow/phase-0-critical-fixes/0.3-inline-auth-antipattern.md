## Mô tả vấn đề

`post.controller.ts` dòng 12-23 và `document.controller.ts` dòng 14-25 tự parse Bearer token và kiểm quyền bên trong controller thay vì dùng middleware:

```ts
// post.controller.ts — listPostsController
if (query.status !== 'published') {
  const authorization = req.header('Authorization');
  if (!authorization?.startsWith('Bearer ')) {
    throw new HttpError(401, 'Bearer token is required');
  }
  const token = authorization.slice('Bearer '.length).trim();
  const payload = verifyAccessToken(token);
  const user = await getCurrentUser(payload.userId);
  if (!user.roles.includes('admin') && !user.permissions.includes('posts.manage')) {
    throw new HttpError(403, 'Permission denied');
  }
}
```

**Vấn đề:** Logic auth bị duplicate, không reusable, bypass middleware pattern.

---

## Mục tiêu

1. Tạo middleware `optionalAuth` — parse token nếu có, attach user, KHÔNG throw nếu không có token
2. Refactor controllers để dùng middleware thay vì inline auth
3. Giữ nguyên behavior: public user thấy published, admin/authorized thấy all statuses

## Cách thực hiện

### Plan A — Tạo `optionalAuth` middleware (KHUYẾN NGHỊ)

**Bước 1:** Tạo middleware mới `backend/src/middlewares/optional-auth.ts`

```ts
import type { RequestHandler } from 'express';
import { getCurrentUser } from '../modules/auth/auth.service.js';
import { verifyAccessToken } from '../utils/jwt.js';

export const optionalAuth: RequestHandler = async (req, _res, next) => {
  try {
    const authorization = req.header('Authorization');

    if (!authorization?.startsWith('Bearer ')) {
      next();
      return;
    }

    const token = authorization.slice('Bearer '.length).trim();

    if (!token) {
      next();
      return;
    }

    const payload = verifyAccessToken(token);
    req.user = await getCurrentUser(payload.userId);
  } catch {
    // Token invalid → treat as unauthenticated, không throw
  }

  next();
};
```

**Bước 2:** Refactor `post.controller.ts` — `listPostsController`

### Plan B — Nếu `optionalAuth` gây side effects

**Lý do:** Middleware chạy trước mọi request, có thể ảnh hưởng routes khác nếu `req.user` bị set không mong muốn.

**Cách xử lý:**
- `optionalAuth` chỉ mount trên routes cụ thể (GET `/posts`, GET `/documents`), KHÔNG mount globally
- Verify các routes khác không bị ảnh hưởng

### Plan C — Giữ inline nhưng extract thành utility

Nếu middleware pattern quá phức tạp:

```ts
// utils/auth-check.ts
export async function tryAuthenticateRequest(req: Request): Promise<AuthUser | null> {
  const authorization = req.header('Authorization');
  if (!authorization?.startsWith('Bearer ')) return null;
  const token = authorization.slice('Bearer '.length).trim();
  if (!token) return null;
  try {
    const payload = verifyAccessToken(token);
    return await getCurrentUser(payload.userId);
  } catch {
    return null;
  }
}
```

Rồi dùng trong controller: `const user = await tryAuthenticateRequest(req);`
