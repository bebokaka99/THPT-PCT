## Mô tả vấn đề

Hiện tại database schema có **2 cặp conflict**:

### Conflict 1: `timetables`
- `004_create_school_modules.sql` tạo `timetables` với cột `class_name`, `semester`, `file_url`, `data_json`, `created_by`
- `013_create_timetables.sql` tạo `timetables` KHÁC với cột `classroom_id`, `school_year`, `semester`, `title`, `is_active`
- Code backend hiện tại (module timetables) dùng schema từ 013

### Conflict 2: `notifications`
- `005_create_system_tables.sql` tạo `notifications` đơn giản: `user_id`, `title`, `message`, `type`, `read_at`
- `012_create_notifications.sql` tạo `notifications` phức tạp hơn: `target_role`, `classroom_id`, `created_by_user_id`, `related_url` + bảng `user_notifications`
- Code backend hiện tại (module notifications) dùng schema từ 012

Nếu drop database và chạy `npm run db:setup` từ đầu → schema 004 tạo `timetables` trước → schema 013 chạy `CREATE TABLE IF NOT EXISTS` nên BỎ QUA → kết quả: bảng `timetables` sai cấu trúc → app crash.

---

## Mục tiêu

1. Loại bỏ duplicate table definitions
2. Đảm bảo `npm run db:setup` chạy clean từ fresh database
3. Giữ backward compatibility nếu database đã có data

---

## Cách thực hiện

### Plan A — Refactor schema files (KHUYẾN NGHỊ)

**Nguyên tắc:** Giữ migration files có số thứ tự, xóa bỏ table definitions cũ không còn dùng.

**Bước 1:** Sửa `004_create_school_modules.sql`
- XÓA phần `CREATE TABLE timetables` (giữ `media_files`, `documents`, `events`)
- XÓA phần `CREATE TABLE events` nếu muốn chuyển sang file riêng (optional)

**Bước 2:** Sửa `005_create_system_tables.sql`
- XÓA toàn bộ phần `CREATE TABLE notifications` (sẽ dùng schema từ 012)

**Bước 3:** Kiểm tra `013_create_timetables.sql`
- Đảm bảo `CREATE TABLE IF NOT EXISTS timetables` có đầy đủ cột mà backend cần
- Giữ nguyên phần `ALTER TABLE` idempotent

**Bước 4:** Kiểm tra `012_create_notifications.sql`
- Đảm bảo `CREATE TABLE IF NOT EXISTS notifications` có đầy đủ cột
- Giữ nguyên phần `ALTER TABLE` idempotent

**Bước 5:** Test fresh database

```bash
# Drop và tạo lại DB (CHỈ TRÊN LOCAL!)
mysql -u root -e "DROP DATABASE IF EXISTS thpt_pct_pt_test; CREATE DATABASE thpt_pct_pt_test;"

# Tạm đổi DB_NAME trong .env sang thpt_pct_pt_test
cd backend
npm run db:setup

# Kiểm tra tables
mysql -u root thpt_pct_pt_test -e "DESCRIBE timetables;"
mysql -u root thpt_pct_pt_test -e "DESCRIBE notifications;"
mysql -u root thpt_pct_pt_test -e "DESCRIBE timetable_items;"
mysql -u root thpt_pct_pt_test -e "DESCRIBE user_notifications;"

# Nếu tất cả đúng cấu trúc → OK
# Đổi lại DB_NAME trong .env
```

### Plan B — Nếu Plan A break existing database

**Lý do:** Database hiện tại đã có data trong `timetables` theo schema cũ (004).

**Cách xử lý:**
1. KHÔNG drop database production
2. Thêm migration mới `014_migrate_old_timetables.sql`:
   - Backup data từ `timetables` cũ
   - Drop `timetables` cũ
   - Tạo `timetables` mới theo schema 013
   - Migrate data sang format mới nếu có thể
3. Chạy migration 014 trên database hiện tại

### Plan C — Nếu Plan A và B đều quá phức tạp

**Cách xử lý đơn giản:**
1. Thêm `DROP TABLE IF EXISTS timetables;` VÀO ĐẦU file `013_create_timetables.sql`
2. Thêm `DROP TABLE IF EXISTS notifications;` VÀO ĐẦU file `012_create_notifications.sql`
3. **Cảnh báo:** Cách này SẼ MẤT DATA nếu tables đã có data → chỉ dùng cho dev
